# oboete (Rust)

Lightweight single-binary memory for coding agents. Rewrite of the TypeScript `oboete-ts`; nothing from it is imported as code.

- **Spec of record**: `docs/spec.md`, the redesign settled with the owner on 2026-09-25/26 (owner decisions, sections 1-8, milestones, acceptance tests from issues). Read it before changing scope. `docs/plan.md` keeps the owner's original wishes, the M0 results and the current code's decisions; its design parts are replaced by the spec. Research behind the spec: `docs/research/redesign-2026-09-24/`.
- **Scope**: finish every feature before any public release (owner, 2026-09-23); build in the spec's section 8 milestone order. The current code keeps running on the owner's machines until the cut-over after milestone 5 (spec 7.5); fix it only for real loss or safety (like #52, #57). Since milestone 2 that code lives on the `v1` branch: the owner's binary is built with `cargo install --path . --locked` on a `v1` checkout, a v1 fix is a PR into `v1`, and `main` is Design B. Never stop, delete or reconfigure claude-mem: the owner decides. New features (agents, sync, update) are tried in the isolated `oboete-dogfood` user before they reach the owner's environment.
- **Process (owner-approved, lighter than the global default)**: spike/milestone notes in `docs/` instead of Spec Kit per PR; one review lane per PR: the Codex GitHub app reviews the PR when it opens and usually each push, but not always (PR #16 skipped one): after every push check that its summary comment names the new head SHA, else comment `@codex review`; answer each round (adopt, or reply why not) and merge when the run on the final head adds nothing (👍 on the PR); `cargo fmt --check`, `cargo clippy`, `cargo test` are the CI; bots: CodeQL only. GitGuardian's hits on the redaction test fixtures are test credentials (the owner skips them). Design-doc PRs are the exception to "merge when the final run adds nothing": a doc that specifies mechanism never converges (PR #29: 21 rounds, 58 real findings). Decide the stop before the loop with a predicate you control, not "the reviewer finds no P1": after two consecutive rounds whose findings are mechanism only (no owner decision changes), move the rest into an issue as acceptance tests for the implementing PRs (like #30), reply, resolve, and merge without a further commit.
- **Implementation**: Claude Code writes the core directly; delegate to Codex/Grok only for independent, parallelizable pieces (agent adapters, donor-module ports).
- **Keys**: API keys live in the owner's `~/<NAME>_KEY.md` files, token on line 2. Never print them; never pass them to subprocess env (see `provider.rs`).
- **Measure, don't assume**: `oboete replay <fixture> --home <tmp>` prints hook latency, VmHWM, provider outcomes. Fixture of record: `../free-mem/test/fixtures/events-1000.jsonl`.
