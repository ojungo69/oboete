# oboete (Rust)

Lightweight single-binary memory for coding agents. Rewrite of the TypeScript `oboete-ts`; nothing from it is imported as code.

- **Spec of record**: `docs/spec.md`, the redesign settled with the owner on 2026-09-25/26 (owner decisions, sections 1-8, milestones, acceptance tests from issues), together with the mandatory `docs/spec-webui.md` owner amendment of 2026-10-02 (#94). Read both before changing scope: the amendment takes precedence over older limitations of the user-facing setup/settings/management UI; other design and safety rules are unchanged. `docs/spec-client-runtime.md` (owner decision 33) is the contract for what comes after the cut-over: live bot adapters (#344), the optional local HTTP service (#345) and selective export (#346); read it before building any of them, and build none before the owner's machines have switched. `docs/plan.md` keeps the owner's original wishes, the M0 results and the current code's decisions; its design parts are replaced by the spec. Research behind the spec: `docs/research/redesign-2026-09-24/`.
- **Scope**: finish every feature before any public release (owner, 2026-09-23); build in the spec's section 8 milestone order. Since 2026-10-02/03 (owner decisions 34-36): the first goal is the owner's own PC running `main` in place of v1; before that switch come milestone 5's forget, mute and capture exclusion, the settings page whole, the resident worker with its viewer always reachable, the three agents (Claude Code, Codex, Grok), and what the owner picks from the claude-mem parity table, since the finished oboete is to be a complete superset of claude-mem; the model-calling evaluations run once, after that, with their cost shown to the owner first, and no stopped evaluation run is started again without the owner. Since 2026-10-14 (owner decision 45) the switch waits for less: the settings page checked on the real screen and fixed, forget as merged, mute and unmute and the correction fixes that can occur on the owner's machines, G23, claude-mem 13.35-13.37's remaining items built as claude-mem behaves, and the rehearsal; milestone 5's retention, withdraw, M22 measurements and independent security review, and #336, come after it. The viewer settings page (#94) is one exception: it is built alongside milestone 3 (owner, 2026-09-30). Milestone 4 is the other: it is built alongside milestone 3, before milestone 3's lines pass (owner decision 32; which of its runs wait: spec 8.4). This PC switched to Design B on 2026-10-15 (spec 7.5): its binary is a `--features local-embed` release built from `main` and installed by rename over `~/.cargo/bin/oboete`, after which the resident worker and viewer move to it by themselves (R9); v1's files there were removed with `oboete migrate --finish` on 2026-10-17, and the `v1` branch is history. Never stop, delete or reconfigure claude-mem: it comes off only as decision 50 says, and the owner decides when. New features (agents, sync, update) are tried in the isolated `oboete-dogfood` user before they reach the owner's environment.
- **Process (the owner's, lighter than the global default)**: spike/milestone notes in `docs/` instead of Spec Kit per PR; review lanes per PR: the Codex GitHub app reviews the PR when it opens and usually each push, but not always (PR #16 skipped one): after every push check that its summary comment names the new head SHA, else comment `@codex review`; answer each round (adopt, or reply why not); a code PR merges when the round on its final head has no blocking finding, that round's other findings that hold going into an issue as acceptance tests for the next PR before the merge, with no further commit (decision 54, 2026-10-22: a finding blocks when it would lose, leak or let someone else alter a record or a secret, show a stored value the gate should mask, break a hook or the store, change which session a record is attributed to, or stop something that works now from working in ordinary use; we judge it, not the reviewer's P1 or P2); `cargo fmt --check`, `cargo clippy`, `cargo test` are the CI; bots: CodeQL, and CodeRabbit (owner, 2026-09-28), which does not review here on its own (fewer than 10 stars): comment `@coderabbitai review` after a PR's last push, and again after the push that answers its findings (its plan gives one review an hour; "Review limit reached" names when to ask again), merge without waiting for it when the other lanes' reviews of the final head are enough (owner, 2026-09-30): Codex and cubic, or while cubic is at its monthly limit Codex and OpenCodeReview where it ran, each finding answered and nothing open; ask it when a slot is free, for the PR its review adds most to, and answer its findings under the PR's stop rule as Codex's; and cubic (owner, 2026-09-28), which reviews a PR when it opens and each later push by itself: read its review of the final head before merging and answer it the same way. cubic's reviews count against 40,000 reviewed lines a month, shared with the owner's other repositories, so its oboete settings on cubic.dev skip `Cargo.lock`, `config/gitleaks.toml`, `src/testdata/**`, `docs/research/**`, `docs/spike/**`, write no PR descriptions, and run an ultrareview (3x the lines) only when asked. OpenCodeReview (OCR, paid per run through the owner's DeepSeek key, and from OpenRouter credits when that key fails) runs only by hand, at a decisive moment (owner, 2026-10-02): the final head of a PR in security scope or with a large change of behaviour, when the other lanes leave it thin (`gh workflow run open-code-review.yml --ref main -f pr_number=<n>`; reviews of different PRs run in parallel): read its review and answer it the same way; a new run for a PR cancels one still in progress, whose cost is then lost (docs/open-code-review.md). `../oboete-work/resolve.sh` (outside the repository, on the owner's machine) resolves Codex threads only, so resolve the other bots' threads one by one. GitGuardian's hits on the redaction test fixtures are test credentials (the owner skips them). Design-doc PRs have their own stop rule: a doc that specifies mechanism never converges (PR #29: 21 rounds, 58 real findings). Decide the stop before the loop with a predicate you control, not "the reviewer finds no P1": after two consecutive rounds whose findings are mechanism only (no owner decision changes), move the rest into an issue as acceptance tests for the implementing PRs (like #30), reply, resolve, and merge without a further commit. Since this PC's switch, every review finding of a code PR that holds is fixed (owner decision 48, 2026-10-16, ending decision 45's rule of fixing only what can occur on the owner's two machines), in the PR or, under decision 54, in the next one; heavy local runs (a test suite, a mutation run, a model review) go one at a time.
- **Implementation**: Claude Code writes the core directly; delegate to Codex/Grok only for independent, parallelizable pieces (agent adapters, donor-module ports).
- **Keys**: API keys live in the owner's `~/<NAME>_KEY.md` files, token on line 2. Never print them; never pass them to subprocess env (see `provider.rs`).
- **Public text**: the repository is public. Issues, PRs, review replies, commit messages and docs carry no Claude Code session link (`https://claude.ai/code/session_…`): a commit has no `Claude-Session:` trailer, and a PR's "Generated with Claude Code" line is plain text with no link and nothing of the owner's conversations: no words of the owner's quoted from a chat, no report of what the owner asked, approved, answered or chose, and no prompt of the owner's from evaluation data (its label id and counts only). A decision is written as what was decided, with its number and date (owner, 2026-10-14).
- **Measure, don't assume**: `oboete replay <fixture> --home <tmp>` prints hook latency, VmHWM, provider outcomes.
