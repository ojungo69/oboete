# claude-mem's work-view

Decision 114 (2026-11-17) serves claude-mem's work-view on oboete's engine: My Work, focus areas, Suggested, Past focus and My Rules ([page.md](../../docs/page.md), "claude-mem's My Work pages"). The spike that came first is [spike/work-view.md](../../docs/spike/work-view.md).

- `upstream/` is the work-view as claude-mem published it, unchanged. It holds the sources, the files outside `src/ui/my-work` they import, and claude-mem's root `package.json`, which sets `"type": "module"`. `LICENSE` and `NOTICE` are claude-mem's. claude-mem's `src/` layout is kept, because the sources' relative imports climb to it.
- `UPSTREAM` names the tag and the commit `upstream/` came from. oboete's `NOTICE` points here rather than repeating them.
- `fetch.sh` makes `upstream/` again from a claude-mem checkout at a tag: `ui/work-view/fetch.sh <checkout> <tag>`. Nothing else changes `upstream/`. A Dependabot pull request that edits its `package-lock.json` is closed, and its advisory is handled where the bundle's packages are checked (step 4 below).
- `patches/` holds oboete's changes, applied in order. Each file they change says "Modified by oboete".
  - `0001-token-and-transport.patch` sends oboete's token header with the requests to the work-view's paths alone, keeps the pages' own key in the browser, and polls in place of claude-mem's event stream. It answers claude-mem's setup probe in the page, and takes the key out of the address once read. A refused token leaves the page's memory and the browser's storage, and nothing a later answer on that page brings keeps it (another tab's is #1100); each poll has a deadline its answers' bodies count against; a snapshot the page would drop moves neither the version seen nor the minute. Every name under `.localhost` is this computer to the pages: claude-mem's own check (`served-from.ts`) takes any name but `localhost`, `127.0.0.1` and `::1` for its cloud viewer. Its tests are `src/ui/my-work/src/live/oboete-token-client.test.ts` (#1085).
  - `0002-build-output.patch` keeps the build inside its copy.
  - `0003-hide-what-oboete-lacks.patch` hides what oboete does not have yet: continuing a conversation, sharing an area and the reads of which areas are shared, usage reports, the team view, the machines, the specification overlay and the installer, its route, its import and its handoff (`src/ui/my-work/src/store/oboete-setup.test.ts`). It hides too the controls whose writes oboete does not take yet, until the pull request that takes each: checking a request, adding a rule, changing an area or a suggested one, and Refresh now (#1085).
  - `0004-oboete-brand.patch` puts in oboete's mark, name, title, favicon and Japanese font fallback, and hides claude-mem's own links.
  - `0005-fonts-as-files.patch` keeps Vite from inlining a font as a `data:` URL, which it would do for one under 4 KiB, typing a `.otc` as `application/octet-stream`. Every font then goes as a file, which `notices.mjs` reads against the package it comes from.
- `build.sh` builds the bundle into `assets/work-view/`:
  - it applies the patches to a copy;
  - it installs the packages with `npm ci --ignore-scripts`;
  - it runs claude-mem's own tests on the patched tree, oboete's beside them, each test held to a minute (`package.json`'s test command; the build stops when that command changes, or when a folder it names has no test left);
  - it type-checks and builds;
  - it writes `THIRD-PARTY-NOTICES.md` with `notices.mjs`, which lists every package and font the bundle holds with its licence. `licences/` holds the texts of the packages that ship none, and the build stops at a package with no text, and at a font inlined as a `data:` URL, which has no file to check: fonts go as files.

  Run it as a user who cannot read your keys: the build's tools run native code even with install scripts off.
- `contract/` holds the contract between oboete's answer and the pages: `snapshot.json`, the answer of `GET /api/work-view` (`src/work_view.rs`) for a synthetic home, which the Rust test `work_view::tests::the_contract_snapshot_is_this_homes_answer` keeps current (it compares the two with times and keyed prints written as their kind; with `OBOETE_CONTRACT_WRITE=1` it writes this run's answer, whatever it is. In the first 15 minutes of a month, when the home's newest goals fall in the month before, it refuses to write and does not compare), `stories.json`, the Build story the adapter writes for each case of `STORIES` in the same Rust file (its test `the_contract_stories_are_the_adapters_answer` keeps it current the same way), `gated.json`, the same home's answer read under rules on the keys the snapshot reads its counts, days and times by and on the shapes the adapter writes (`the_contract_gated_snapshot_is_a_gate_homes_answer`, #1089), `gated-stories.json`, the Build stories a rule finds a value in (`a_story_is_read_whole_before_any_mask`), and a Node test that runs claude-mem's mapper, unchanged, over all four (`node --test 'ui/work-view/contract/*.test.mjs'`, which the workflow runs again with `TZ=America/Los_Angeles`, as the pages run in the browser's zone). A bump of claude-mem runs the new mapper over the same answer.
- `notices.test.mjs` runs `notices.mjs` over small built trees it makes, `scripts.test.mjs` runs `build.sh` and `fetch.sh` in small checkouts it makes, and `bundle.test.mjs` reads the committed bundle: no part of the installer is in it, by its chunks' names and by the setup routes its scripts call (`node --test 'ui/work-view/*.test.mjs'`).
- `.github/workflows/work-view.yml` runs `build.sh` again in CI. It fails when the bundle it makes differs from the committed one by a byte.

The bundle is not served yet. Its data is `GET /api/work-view` (`src/work_view.rs`), which answers at the main page's address with its token; the pages' own address and their token come in the pull request that serves them.

## Following claude-mem

At each new release that is wanted:

1. Read the contract diff first: `git diff <old> <new> -- src/ui/my-work/src/live/ src/ui/my-work/src/data.ts src/ui/my-work/src/data-rules.ts src/ui/my-work/test-fixtures/ src/services/worker/http/routes/WorkViewRoutes.ts src/services/work-view/` in the claude-mem checkout.
2. Run `fetch.sh` with the new tag, then the contract test: the new mapper must read oboete's answer. A mapper that changed what it reads is answered in `src/work_view.rs`, and its Rust test writes the snapshot again (`OBOETE_CONTRACT_WRITE=1`).
3. Run `build.sh`. When a patch no longer applies, port the patches onto the new tag: in a scratch git repository, commit the old tag's tree (commit `old`), then each patch as a commit of its own, in order, on a branch; commit the new tag's tree on a branch of its own from `old` (commit `new`), and replay the patches with `git rebase --onto new old <the patches' branch>`, resolving each conflict there. Write the patches again from the rebased commits into an empty folder (`git format-patch -o <the folder> new..<the patches' branch>`, with their names kept), check that it holds one patch for each of those commits (`git rev-list --count new..<the patches' branch>`, which is at least one), then replace `patches/` with that folder and run `build.sh` with them. When the rebase left no commit, keep `patches/` as it is and see what the new tag changed: `build.sh` stops at an empty `patches/`, as oboete's patches carry its token, its transport and its name. A patch whose commit the rebase emptied is then gone, not left behind.
4. Check every package the bundle holds (decision 114): where it comes from, what it runs when installed, and the advisories against it. The diff of `assets/work-view/THIRD-PARTY-NOTICES.md` shows which packages are new or changed; for one whose locked source, version and integrity hash are those of the last update, the last check of its source and of what it installs stands, and its advisories are checked again. A text in `licences/` names the versions it was checked for, and the build stops at another: read that package's licence again and add the version.
5. Commit `upstream/`, `UPSTREAM`, the patches, the texts in `licences/` that changed and `assets/work-view/` together, with `src/work_view.rs` and the snapshot written again when step 2 changed them, after the Node test has run over the new snapshot. `NOTICE` names `UPSTREAM`, so it does not change.

## A run that was killed

`build.sh` and `fetch.sh` put things back however they end, but a run killed with SIGKILL, or a machine that stopped, runs no handler and leaves `ui/work-view/.lock` behind; so does a signal at the moment a run takes the lock, before its handler is set. With no build or fetch running, what the run's reserved folder holds says how far it got. No reserved folder: the run moved nothing, or it had finished and only its lock was left; the tree and the bundle in place are whole. While a reserved folder of `fetch.sh`'s that holds an `UPSTREAM` is in `ui/work-view/`, `build.sh` and `fetch.sh` stop and name it. They stop too at one the user running them cannot look in: `mktemp` makes it its owner's alone, so a build run as another user than the fetch was cannot tell. Look in it as the user who ran the fetch.

A reserved folder still there is a killed run's, one for each such run; a run killed before it made its folder, or after it removed it, leaves only the lock, as above. The two kinds are recovered apart, each from its own newest folder: `ls -dt ui/work-view/.upstream.*` for the tree, `ls -dt assets/.work-view.*` for the bundle, newest first. An older folder's `old` is from before a later run, not the one to put back. With more than one folder of a kind, or when you cannot tell which is the newest, put none of that kind back. Once you are sure no build or fetch is running, move that kind's folders aside, outside `ui/work-view/` and `assets/`, with the tree or bundle in place and the tree's `UPSTREAM` (a rollback may have put back a tree fetched and not yet committed), then remove the lock, and only then make that kind again: the tree first, with `fetch.sh` and the commit the newest folder's `UPSTREAM` records (or the tag, while it still names that commit), then the bundle with `build.sh`. When the newest folder holds no `UPSTREAM` (its run was killed before it wrote one, or after its swap), put back the tree and `UPSTREAM` you moved aside if they are a pair, or fetch a commit another folder's `UPSTREAM` records. Keep each folder you moved aside that holds an `UPSTREAM` until `ui/work-view/UPSTREAM` names the commit it records, or you give that fetch up; the others, until the tree and the bundle in place are both whole again.

- `build.sh`, `assets/.work-view.*`:
  - `old`, and no `assets/work-view/`: the old bundle was moved aside and the new one never moved in. Move `old` back to `assets/work-view`.
  - Neither `old` nor `assets/work-view/`: there was no bundle before, and none moved in. Run `build.sh` again once the lock is gone.
  - Anything else: the bundle in place is whole.
- `fetch.sh`, `ui/work-view/.upstream.*`:
  - No `UPSTREAM`: the run stopped before the swap, or after it was done. The tree in place and its `UPSTREAM` line are a pair.
  - `UPSTREAM` and `new`: the new tree never moved in. With `old` too, the old tree was moved aside: move it back to `ui/work-view/upstream`.
  - `UPSTREAM` and `old`, and no `new`: the new tree moved in, without its line. Remove `ui/work-view/upstream/` if it is there, and move `old` back to `ui/work-view/upstream`.
  - `UPSTREAM` alone: a first fetch's new tree moved in, or a run putting things back had moved the old tree back, which may be a tree fetched before and not yet committed. Read the reserved folder's `UPSTREAM` first: it names the tag and the commit the run was fetching, and after a first fetch it may be the only record of them. Check that the tag still names that commit (`git -C <checkout> rev-parse <tag>^{commit}`); if it has moved, fetch the commit itself instead of the tag (`fetch.sh <checkout> <commit>`). Move the folder aside, outside `ui/work-view/`, and move `ui/work-view/upstream/` and `ui/work-view/UPSTREAM` aside too, as a pair: they may be the only copy of a tree not yet committed, and its record. Then remove the lock and run `fetch.sh`: it makes the tree and its `UPSTREAM` line again. Remove what you moved aside only once `ui/work-view/UPSTREAM` names the recorded commit, or once you choose to give up that fetch; a retry that fails leaves both to read again.
- Or, to drop what is not committed, put back what is: move `ui/work-view/upstream/`, `ui/work-view/UPSTREAM` and `assets/work-view/` aside, run `git restore --source=HEAD --staged --worktree -- ui/work-view/upstream ui/work-view/UPSTREAM assets/work-view`, and remove what was moved aside. This discards a fetch or a build not yet committed. A plain checkout over the trees would leave the files a partial swap added.

Then remove the reserved folder, and only then `ui/work-view/.lock` (for `UPSTREAM` alone, and for more than one folder of a kind, the steps above say when).
