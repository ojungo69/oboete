## Runtime entry points and observed surfaces

### OpenCode plugin

- The source of truth is `packages/opencode-plugin/.opencode/plugins/codemem.js`. It receives OpenCode `message.updated`, `message.created`, `message.appended`, and `message.part.updated` events (`packages/opencode-plugin/.opencode/plugins/codemem.js:3441-3509`), session boundaries/errors (`packages/opencode-plugin/.opencode/plugins/codemem.js:3586-3631`), and `tool.execute.after` (`packages/opencode-plugin/.opencode/plugins/codemem.js:3633-3674`).
- It records prompt text, completed assistant text/usage, tool arguments/results/errors, and file paths reported by Read/Edit/Write/apply_patch tool events (`packages/opencode-plugin/.opencode/plugins/codemem.js:3502-3583`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3639-3667`). The file sets are in-memory session context (`packages/opencode-plugin/.opencode/plugins/codemem.js:2021-2038`); this path does not open or watch those files.
- Each captured event is immediately offered to the viewer's `/api/raw-events` endpoint; when the stream is unavailable it invokes `codemem enqueue-raw-event` as a CLI fallback (`packages/opencode-plugin/.opencode/plugins/codemem.js:1747-1768`, `packages/opencode-plugin/.opencode/plugins/codemem.js:1792-1934`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3202-3235`). The in-memory queue is retried/flushed at `/new`, `session.error`, `session.idle`, `session.created`, or thresholds of 50 tools, 15 prompts, or ten minutes (`packages/opencode-plugin/.opencode/plugins/codemem.js:2040-2055`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3237-3305`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3522-3553`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3586-3609`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3670-3673`).
- With viewer auto-start enabled, `session.created` starts a detached viewer and a 60-second health monitor; repeated failed probes can restart it. `session.deleted` can stop it (`packages/opencode-plugin/.opencode/plugins/codemem.js:27`, `packages/opencode-plugin/.opencode/plugins/codemem.js:62-202`, `packages/opencode-plugin/.opencode/plugins/codemem.js:2223-2247`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3110-3128`, `packages/opencode-plugin/.opencode/plugins/codemem.js:3606-3631`).
- Optional plugin diagnostics append to a configured log; warnings/errors have an error-log path (`packages/opencode-plugin/.opencode/plugins/codemem.js:305-318`, `packages/opencode-plugin/.opencode/plugins/codemem.js:349-367`, `packages/opencode-plugin/.opencode/plugins/codemem.js:1579-1598`).

[2026-08-12 訂正: 初版は方向を逆に記載していた — ソース照合済み] Pack construction records a `usage_events` row (`packages/core/src/pack.ts:1109-1124`, `packages/core/src/pack.ts:1980-2003`). ## Viewer observer and sweeper

- `codemem serve` creates one `ObserverClient`, opens the shared `MemoryStore`, starts `RawEventSweeper`, and starts the viewer; when sync is enabled it also schedules the sync daemon. It writes a viewer PID file and removes it during shutdown (`packages/cli/src/commands/serve.ts:622-647`, `packages/cli/src/commands/serve.ts:649-766`, `packages/cli/src/commands/serve.ts:704-716`, `packages/cli/src/commands/serve.ts:780-800`).
- Foreground serve also launches a detached maintenance worker and writes/removes its PID record (`packages/cli/src/commands/serve.ts:419-471`, `packages/cli/src/commands/serve.ts:704-716`, `packages/cli/src/commands/serve.ts:780-827`). That worker opens another `MemoryStore`, checkpoints WAL every five minutes, and starts vector migration, sequential schema/data backfills, and optional sync retention (`packages/cli/src/maintenance-worker-runtime.ts:161-257`).
- Raw-event HTTP writes are `/api/raw-events`, `/api/claude-hooks`, and `/api/codex-hooks`. They call `recordRawEventsBatch`/`recordRawEvent` and nudge the sweeper (`packages/viewer-server/src/routes/raw-events.ts:163-377`, `packages/viewer-server/src/routes/raw-events.ts:390-427`, `packages/viewer-server/src/routes/raw-events.ts:440-474`).
- The sweeper is a self-scheduling timer, not an OS file watcher. Default sweep interval is 30 seconds, default idle threshold 120 seconds, and optional auto-flush debounce defaults to 60 seconds (`packages/core/src/raw-event-sweeper.ts:76-104`, `packages/core/src/raw-event-sweeper.ts:127-136`, `packages/core/src/raw-event-sweeper.ts:178-251`, `packages/core/src/raw-event-sweeper.ts:322-365`).
- A tick purges aged raw events when retention is enabled, marks stuck batches, flushes pending-queue streams, and flushes idle streams (`packages/core/src/raw-event-sweeper.ts:371-476`). `flushRawEvents` reads unflushed events, creates/claims a batch, invokes the ingest pipeline, records failure or completion, and advances flush state (`packages/core/src/raw-event-flush.ts:210-373`).
- The ingest pipeline builds a transcript, calls the observer, and writes derived session/memory/summary data and associated metadata through `MemoryStore`; raw-event flushes treat no storable output as a failed flush (`packages/core/src/ingest-pipeline.ts:349-581`, `packages/core/src/ingest-pipeline.ts:677-859`). Vector work can load the lazy embedding backend and write vector state (`packages/core/src/embeddings.ts:124-190`, `packages/core/src/vectors.ts:515-578`).
- Observer provider selection reads codemem/OpenCode config, environment variables, OAuth cache, optional credential files/commands, or delegates authentication to Claude/Codex sidecars (`packages/core/src/observer-client.ts:427-700`, `packages/core/src/observer-client.ts:1240-1515`, `packages/core/src/observer-client.ts:1801-1879`, `packages/core/src/observer-auth.ts:49-196`, `packages/core/src/observer-auth.ts:245-361`). API backends write only remote request traffic; the Codex sidecar writes a temporary final-message file and deletes it (`packages/core/src/observer-client.ts:2273-2377`, `packages/core/src/observer-client.ts:2503-2589`).

## Filesystem-watcher check

Static searches over tracked TypeScript/JavaScript found no use of `fs.watch`, `fs.watchFile`, `chokidar`, or `node-watch`. Session observation is event/hook driven, transcript files are read at hook boundaries, viewer health is interval-polled over HTTP, and raw-event processing is timer/DB-queue driven.
