# Design B, section 5: devices and sync (draft for audit, 2026-09-25)

- Topology: a star through one hub, a Cloudflare Worker plus one Durable Object (DO) per user that holds an append-only op log. Devices push and pull over HTTP with an ordered cursor; a WebSocket only wakes a pull (M19). One device needs no hub. More than one device needs the hub (decision 12). The hub URL is configured by the user; no URL is built in (M19). Public users deploy their own hub (one command, via wrangler, into their own Cloudflare account).
- What travels: claims (full rows), owner corrections, manifests, digests (they cite claim uids; staleness is computed locally), vectors with embedder_id, tombstones, repo-touch sets, prompts (decision 2 of 2026-09-23). Raw travels only if raw sync was chosen at setup (off by default, decision 14), to R2 through the hub.
- Exclusion: per-repo sync exclusion is checked at send time against every repo a session touched; content ops of an excluded repo never leave; control ops (tombstones, touch-set updates) always travel (decision 11). The first sync lists repos and counts and asks for confirmation.
- Order and conflicts: ops are idempotent by (uid, rev). Current state is computed on each device from the synced claims (chain tips), so every device reaches the same state once caught up. Concurrent supersession is ordered by (valid_from = anchor time, device, seq) and flagged in the viewer; an op whose timestamp differs from its receive time by more than 5 minutes raises a clock-skew alarm (M7).
- Version skew: every op carries a format version; an older binary parks ops it does not understand, never applies or drops them, and doctor names the version needed (M17).
- Deletion: tombstones are replicated and never compacted. The hub replaces the payload with the tombstone, deletes the Vectorize ids and R2 objects. Every inbound path checks a deny-list (sync, import, re-derive, restore). An offline device purges on its next sync.
- Catch-up: bounded catch-up after a long offline period (S6); a new device gets the last 30 days first, then backfills (M22 measures the time and bytes).
- Timing: the worker pushes after committing new ops and pulls every 30-60 s while active and when it refreshes a SessionStart packet; target p95 of 5 minutes from curation to availability on another device.
- Auth: per-device credentials that can be revoked one by one; the owner turns on Cloudflare two-factor authentication before sync starts (decision 16 of 2026-09-23).
- Remote MCP for the Claude app: through the hub with OAuth (workers-oauth-provider) and per-repo grants; search, get and timeline never cross grants, including `all` and direct ids (R09). Remote search uses Vectorize (stop line USD 1.5 per month) and the DO's full-text index if the DO supports FTS5 trigram (unknown).
- Other devices' manifests: a labelled block when that device has been idle over 30 minutes and its manifest is newer (S4-13).
- Donor: claude-mem CloudSync / SyncHub / canonical-content (Apache-2.0, credited in NOTICE); a self-host spike comes before the hub build (M19).
- Later: a cloud curator as another consumer of synced raw (section 1); folder transport (decision 12).
