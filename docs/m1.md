# M1 — 3 agent 捕捉・provider chain・伏せ字・検索・MCP・viewer・setup (2026-09-22 着手)

完了条件: この PC に claude-mem と併用で導入し、owner が 1 週間実使用して判定する。
仕様の正本は `docs/plan.md`。ここは M1 の決定事項・checklist・計測結果だけを置く。

## 決定事項 (M1 で確定したもの)

1. **agent 判別はコマンド引数で固定** (`oboete hook claude|codex|grok <event>`)。ただし Grok Build は
   `~/.claude/settings.json` の hook も互換層として実行するので、`claude` として呼ばれた hook が
   Grok 形の payload (`hookEventName` / `sessionId` の camelCase) を受け取ったら agent を `grok` に
   読み替える。`~/.grok/hooks/oboete.json` が存在するときはその Grok 形 payload を捨てる
   (Grok 自身の hook が同じイベントを届けるため。時間窓の重複判定は使わない)。
2. **自己捕捉ガード**: 要約に使う CLI (`claude -p` / `codex exec` / `grok -p` / `agy -p`) は自分の
   hook を発火させる。provider 起動時に `OBOETE_SKIP=1` を渡し、hook はこの変数があれば DB を
   開く前に exit 0 する (provider.rs の秘密系 env 除去は `KEY/TOKEN/SECRET/PASSWORD` を含む名前
   だけなので、この名前は残る)。
3. **resume では注入しない** (`source == "resume"` は transcript に前回の注入が残っている)。
   **Grok Build は SessionStart / UserPromptSubmit の stdout を捨てる** (公式 docs、研究で確認) ので、
   Grok への注入はセッション最初の `PreToolUse` の `additionalContext` で行う (tool 実行後に
   モデルへ届く。10,000 字で切られる)。`sessions.injected_at` で 1 回きりにする。
4. **Codex の Stop には assistant 本文が無い** → `transcript_path` の rollout JSONL の末尾から
   `response_item` / `message` / `role: assistant` の最後の `output_text` を読む (末尾だけ seek、
   全読みしない)。
5. **伏せ字は gitleaks の規則を同梱** (`config/gitleaks.toml`、MIT、222 規則、Rust regex で全部
   コンパイル可能)。hook の 20 ms 予算を守るため、gitleaks と同じ設計にする: 規則ごとの
   `keywords` を大文字小文字無視の Aho-Corasick で先に当て、当たった規則の regex だけをその場で
   コンパイルし、`entropy` 付き規則は Shannon entropy でふるう。保存前 (hook) と送信前 (observe)
   の 2 か所で同じ関数を通す。効果は replay の `hook_spawn_ms` で計測して記録する。
6. **provider chain の既定** (2026-09-23 に全部 probe 済み): groq `openai/gpt-oss-120b` →
   groq `openai/gpt-oss-20b` (モデル別に 8,000 TPM の枠が分かれる) → agy → claude (sonnet) →
   OpenRouter `nvidia/nemotron-3-super-120b-a12b:free` (`models` fallback = `qwen/qwen3.8-27b:free`、
   `provider.require_parameters`) → NIM `nvidia/nemotron-3-super-120b-a12b` (OpenAI 形式の
   `response_format` が通る。`nvext.guided_json` は hosted では 400) → Mistral `mistral-small-latest`
   → codex → grok。Groq 無料枠は **1,000 回/日・8,000 トークン/分** (実測ヘッダ)。M0 の 429 は
   TPM 超過。429 で reset が 60 秒以内なら 1 回だけ待って再試行 (OpenRouter は失敗も日次枠を
   消費するので待たない)。それでも 429 なら 45 秒、5xx/timeout/起動失敗なら 10 分のクールダウン。
   schema 不一致の 400 (Groq が稀に返す "Generated JSON does not match the expected schema") と
   解析不能な応答はその場限りで次へ。provider ごとの日次予算は継続。
   **owner 確認事項**: OpenRouter の無料枠 1,000 回/日は 09-22 時点で他ツールが使い切っていた
   (`free-models-per-day-high-balance`)。Mistral は `x-ratelimit-limit-req-minute: 0` で全部 429
   (Experiment tier が有効になっていない模様。console で確認が要る)。
7. **サブスク CLI は最小構成で呼ぶ**: 素の `claude -p` は 67k 入力トークン (CLAUDE.md・plugin・
   tool・MCP 定義) を毎回積む。`--bare` は keychain も読まないので "Not logged in" になり使えない。
   `--setting-sources "" --tools "" --strict-mcp-config --no-session-persistence
   --settings '{"disableAllHooks":true}' --model sonnet` で 7k まで落ちる (`--strict-mcp-config`
   が無いと MCP の tool 定義だけで 80k)。grok は `--tools "" --max-turns 1`、codex は
   `--ephemeral --skip-git-repo-check --sandbox read-only -c model_reasoning_effort=low`、
   agy は現状のまま。全部に `OBOETE_SKIP=1` を渡す (grok / codex には hook を切る口が無い)。
   構造化出力の取り出し口 (実測 2026-09-22): claude = `structured_output` /
   grok = `structuredOutput` / agy = `structured_output` / codex = `-o` ファイル。
8. **要約プロンプト**: 出力言語は config `[summary] language` (既定 `ja`) で固定し transcript から
   推定しない。覚える価値が無いセッションは `observations: []` でよいと明示する。
9. **検索**: FTS5 `trigram` tokenizer 1 本 (CJK も文字単位で索引される)。3 文字未満の語だけ
   `LIKE` (ESCAPE 付きの literal、ASCII のみ大小同一視) にして MATCH と AND で結合する。意味検索は `[embedding] provider = "none"` を既定にし、`workers-ai`
   (bge-m3) は導入後に追加、`local` (fastembed/ONNX、約 300 MB) は M3 に送る。
   実装 (PR5): 索引は `fts` 1 表に observations / summaries の写しを持つ (external content と
   trigger は使わない。`apply_batch` の同じトランザクションで挿入)。旧 DB への初回作成は
   `BEGIN IMMEDIATE` の二重チェックで 1 回だけ backfill する (3 agent の hook が同時に open しても
   二重化しない。反証ワークフローで実証)。知識行の `ts` はセッションの `last_event_at`
   (要約した時刻ではない)。CLI: `oboete search <語…> [--all] [--limit N]` / `get o12|s5` /
   `timeline [--all]`。`search … | head` で panic しない。`-` で始まる語は `--` の後ろに置く。
10. **MCP** は rmcp (公式 SDK) の stdio サーバー。tokio runtime は `mcp` / `view` の中でだけ作り、
    hook の起動時間に影響させない (replay で確認)。tools = `search` / `get` / `timeline`。
    実装 (PR6): `oboete mcp` は `search.rs` の関数を薄く包む 3 tool (`Parameters<T>` + schemars で
    入力 schema、結果は text)。既定の検索範囲はサーバーの cwd の repo (agent は project dir で起動する)、
    `all` / `repo` 引数で広げる。登録は `setup` が行う: Claude Code は `~/.claude.json` の
    `mcpServers.oboete` (`type: stdio`)、Codex は `~/.codex/config.toml`、Grok Build は
    `~/.grok/config.toml` の `[mcp_servers.oboete]` (command / args。Grok は `~/.claude.json` も互換で
    読むが同名は自前の方が勝つ)。`--remove` は自分の項目だけ消す。`doctor` に `mcp server` 欄。
    rmcp 3.4 の要点: `ContentBlock::text`、`ServerConfig::new(caps).with_server_info(..)
    .with_instructions(..)`、`#[tool_handler(router = self.tool_router)]` (省略すると呼び出しごとに
    router を作り直す)。rmcp + tokio でバイナリが 13.4 MB になったので `strip = true` (10.4 MB)。
11. **viewer** は tiny_http + 同梱 HTML 1 枚 (SPA のビルド無し)。
12. **setup** は hook コマンドに `current_exe()` の絶対パスを書く。既存ファイルは初回のみ
    `.bak` を取る。`oboete setup --remove` で自分の項目だけ外す。Codex は `hooks.json` の
    マージ後の位置から trust 行 (`[hooks.state."<path>:<event>:<group>:<index>"]`) を
    `config.toml` に `toml_edit` で追記する (hash 算出は本機の既存行 2 本で検証済み。
    `statusMessage` は付けない)。導入後は各 agent で実セッションを 1 回起動して発火を確認する。
13. **順序**: capture (3 agent) → 伏せ字 → chain → **導入** → 検索 → MCP → viewer。
    導入は自己捕捉ガードと Grok 二重発火の抑止が実証されてから。

## 調査で確定したこと (2026-09-23、研究ワークフロー 6 題 + 反証 + 実 probe)

- Grok Build: `~/.grok/hooks/*.json` を全部読む。`~/.claude/settings.json` も互換層として読む
  (`GROK_CLAUDE_HOOKS_ENABLED=0` / `[compat.claude] hooks=false` で止まるが、owner の他の
  Claude hook も止まるので使わない → 1 の規則で捨てる)。hook 設定はセッション開始時に 1 回だけ
  読む (setup 後は再起動)。PostToolUse の exit 2 は stderr がモデルに渡る (常に exit 0)。
- Codex 0.155: trust 行を非対話で入れる公式 CLI は無い。hash は手元の既存行 2 本と一致。
  Stop は `last_assistant_message` を持つ (docs 更新済み。無いときは transcript 末尾)。
  `PostToolUseFailure` は Codex に無い。`additionalContextLimit = 0` で長文 context の
  ファイル退避を止める。
- Claude Code 2.1.278: SessionEnd の既定予算は 1.5 秒 (timeout で延ばせる)。`--json-schema` の
  結果は `structured_output`。規約: 未改変バイナリ + 自分の認証なら自動化は明示的に可
  (`claude setup-token` が CI 用に用意されている)。
- gitleaks: 222 規則。Rust regex では ASCII モード (`unicode(false)`) が Go RE2 の `\w` と同義で
  コンパイルが 30 倍速い (generic-api-key: 90 ms → 3 ms、debug)。allowlist の regex 4 本は
  Rust で通らない (`{\d+}`, `[^]]`) が、伏せ字が増える方向にしか効かない。
- sqlite-vec 0.1.9 + rusqlite ≥ 0.34 は `auto_extension::register_auto_extension`。vec0 の
  KNN で `k` が metadata filter より先に効いて件数が減ることがある (over-fetch する)。
  fastembed は crates.io 5.17 (7.x は無い)、ort が必須依存なので feature gate は crate 単位。
- rmcp 3.4 は tokio 必須。tool 側のエラーは `CallToolResult::error`、protocol エラーと区別する。
