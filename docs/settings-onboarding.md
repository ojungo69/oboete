# W6 guided first run and configuration recovery

This slice follows step 2 of the owner-approved W6 plan, from main `0a3b1366`.
The authority is spec.md §7.2, spec-webui.md and settings-coverage.md. Root is the
only source writer. The installed v1, owner homes, claude-mem, held evaluations
and PC cutover remain outside this work.

Compose the existing settings, provider, agent preview/confirmation and read-only
diagnostics into a Japanese/English journey. Four AI tiers edit the existing
validated settings payload; they introduce no profile store, provider or model.
Keep connection tests separate, and distinguish registration from login and live
use. The final step records an ordinary harmless phrase in the selected agent
and searches it through the existing UI. A private native-hook/browser fixture
proves that journey without calling an agent or model. It does not replace S5's
separate timed write/index/FTS/MCP-get-and-delete probe.

Invalid configuration recovery is a fixed operation: preview current bounded
bytes without writing, require a random confirmation bound server-side to their
version and file/home identity, retain a verified owner-only copy of those exact bytes, then install a
validated configuration with curation, embeddings, paid usage, resident mode,
prompt-text saving and memory injection off. Other capture uses built-in redaction;
custom redaction rules and other custom settings return to defaults. Already
admitted work may finish. Keep stores, agent files and key files. Refuse stale input, unsafe storage or
failed backup/staging; preserve any already-created recoverable copy. No raw
editor, arbitrary path, shell execution, model call or automatic retry is added.
Use the shared settings lock/stager and existing private-storage checks. Platform
support is labelled by actual private-storage support, not assumed from Unix mode.
Only one current confirmation is kept per viewer. A fresh preview or viewer restart
invalidates the old nonce; an admitted start consumes it before any file mutation.

The public seams under test are the guarded recovery HTTP operation, the existing
settings-save payload and the native capture → FTS → browser search journey, as
already selected by the accepted plan. Retain literal red/green evidence, current
source pins, focused/full fmt/clippy/Rust/Node checks, JA/EN browser evidence and
two independent review axes. Final-head CI, security, Sonar and actual review
requirements apply before merge. Port/token activation remains W6 step 3; #94
stays open until the whole coverage contract is satisfied.

Provider policy text is checked against primary sources on 2026-10-08: Anthropic's
[authentication policy](https://code.claude.com/docs/en/legal-and-compliance),
OpenCode's [Go policy](https://opencode.ai/docs/go/),
[terms](https://opencode.ai/legal/terms-of-service) and
[privacy policy](https://opencode.ai/legal/privacy-policy). Quote only short
excerpts and explain remaining restrictions in plain language. Do not infer login,
free quota, credentials or a passing isolation check from a launch file.

Private Linux acceptance uses a genuinely missing configuration, a single explicit
None-tier/resident-off Save, separate Codex wiring and read-only diagnostics, then
the generated native hook and a no-inference FTS drain before JA/EN UI search.
Invalid-settings recovery retains an exact 0600 copy and the earlier searchable
record and agent files. A separate browser transport injection covers initial
repository-list failure and explicit Retry, retaining All and one search request.
It is not a native commit or a live-agent/model test. The source/binary/flow pins,
private-process cleanup and final checks are recorded with the implementing PR.
Private recovery storage on macOS/Windows still waits for #281; S5 and port/token
activation keep their independent completion requirements.
